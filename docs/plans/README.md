# Design plans

The design documents written before each feature was built. Every plan here
describes work that shipped -- the code it names is in `src/` today -- so they
are accurate about *shape*, and they are the only record of the reasoning:
which alternatives were weighed, what was deliberately deferred, and why the
constraints are what they are. That reasoning is not recoverable from the code,
which is why these are kept.

They are not user documentation and they are not updated as the code evolves.
Read them for intent, not as a description of the current implementation.

What belongs here: a plan that argues for a decision. What does not: status
reports, "migration complete" summaries, and investigation write-ups whose
conclusions have since been folded into the code or into `guides/`.

For documentation that is kept current, see [../README.md](../README.md).
